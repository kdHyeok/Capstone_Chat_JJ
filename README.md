# Chat JJ

전주대학교 공지사항과 학사 정보를 자연어로 찾을 수 있도록 만든 스마트 캠퍼스 안내 챗봇입니다. 이 저장소는 챗봇이 참고할 공지 데이터를 수집·정제하고, 검색 가능한 형태로 구조화한 데이터 파이프라인을 정리합니다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 기간 | 2024.03 ~ 2024.06 |
| 형태 | 전주대학교 캡스톤디자인 팀 프로젝트 |
| 목표 | 교내 공지사항과 학사 정보를 수집·정리해 챗봇 검색 데이터로 제공 |
| 담당 범위 | 공지 크롤링, 본문 정제, 이미지 OCR, 마감일 추출, 카테고리 분류 |

Chat JJ는 여러 게시판에 흩어진 공지 정보를 사용자가 자연어로 조회할 수 있도록 지원합니다. 이미지형 공지, 다양한 날짜 표현, 학사·장학·행사 등 서로 다른 성격의 공지를 챗봇 검색에 활용 가능한 데이터로 구조화합니다.

## 2. 전체 시스템 구조

![Chat JJ 전체 시스템 구조](docs/assets/cj-system-overview.svg)

전체 서비스는 앱, 백엔드, AI 서버, 데이터 파이프라인이 분리된 구조입니다.

```text
Flutter 앱
→ Spring Boot 백엔드
→ Quart AI 서버
→ ChromaDB / CSV 검색
→ Ollama LLM 응답 생성
```

| 레포 | 역할 |
|---|---|
| `CJ_Front` | Flutter 앱 화면, 로그인, 챗봇 UI |
| `CJ_Back` | 인증, 채팅 API, AI 서버 중계, MySQL/Redis 저장 |
| `CJ_AI` | RAG 검색, SBERT 유사도, Ollama 호출, 다국어 응답 |
| `CJ_Scraping` | 공지 크롤링, OCR, 마감일 추출, 카테고리 분류 |
| `CJ_Server` | 서버 배포와 운영 자료 |

자세한 호출 흐름은 [전체 시스템 구조](docs/system-architecture.md)에서 확인할 수 있습니다.

## 3. 크롤링 파트 구조

![Chat JJ 공지 데이터 파이프라인](docs/assets/cj-data-pipeline.svg)

이 저장소의 핵심은 공지 데이터를 챗봇이 사용할 수 있는 형태로 만드는 과정입니다.

```text
공지 목록 수집
→ 상세 본문 수집
→ 이미지 링크 추출
→ OCR 텍스트 보강
→ 마감일 추출
→ 카테고리 분류
→ CSV 생성
```

### 레포지토리 구조

| 파일 | 내용 |
|---|---|
| `01_공지_통합_크롤링_파이프라인.ipynb` | 공지 수집부터 본문/OCR/마감일/카테고리 분류까지 전체 흐름을 통합한 노트북 |
| `02_공지_본문_OCR_마감일_추출.ipynb` | 공지 목록·상세 페이지 크롤링, 본문 추출, 이미지 OCR, 마감일 추출 노트북 |
| `03_공지_카테고리_분류_점수화.ipynb` | 공지 제목·본문·부서 기반 카테고리 분류 기준과 점수화 로직 |
| `04_통합공지_카테고리분류_결과.csv` | 통합공지 기반 검색/RAG 원천 데이터 |
| `05_학사공지_카테고리분류_결과.csv` | 학사공지 기반 검색/RAG 원천 데이터 |
| `docs/system-architecture.md` | 팀 프로젝트 전체 시스템 구조와 레포 간 연결 설명 |
| `docs/assets/*.svg` | 전체 구조, 질문 처리 시퀀스, 데이터 파이프라인 도표 |

| 영역 | 기술 |

## 5. 구현 방향

### 공지 데이터 수집

전주대학교 통합공지와 학사공지 게시판을 순회하며 제목, 부서, 등록일, 상세 링크를 수집했습니다. 상세 페이지에서는 본문과 첨부 정보를 함께 정리해 챗봇 검색에 필요한 원천 데이터를 만들었습니다.

### 이미지형 공지 보강

포스터나 이미지 중심 공지는 본문 텍스트만으로 검색하기 어렵습니다. 이미지 링크를 수집하고 OCR을 적용해 본문에 없는 텍스트를 보완했습니다.

### 마감일 추출

공지마다 날짜 표현 방식이 달라 정규표현식 기반으로 날짜 후보를 추출했습니다. 신청 기간, 모집 마감, 선착순 여부처럼 사용자가 자주 묻는 정보를 검색 데이터에 반영했습니다.

### 카테고리 분류

공지 제목, 본문, 부서 정보를 바탕으로 카테고리 점수를 계산했습니다. 이를 통해 챗봇이 질문과 관련 있는 공지를 먼저 찾을 수 있도록 후보 범위를 줄였습니다.

| 분류 축 예시 | 활용 목적 |
|---|---|
| 수업/강의, 시험/평가 | 학사 질문 후보 축소 |
| 졸업/학위, 등록/휴학/복학 | 절차성 공지 검색 |
| 장학/재정 | 장학금·지원금 질문 대응 |
| 행사/일정, 행정/공지 | 교내 프로그램·일정 안내 |

## 6. 트러블 슈팅

| 문제 | 대응 |
|---|---|
| 이미지로만 올라온 공지는 텍스트 검색이 어려움 | 이미지 링크 수집 후 OCR로 텍스트 보강 |
| 공지마다 날짜 표현 방식이 다름 | 정규표현식으로 날짜 후보를 추출하고 후처리 |
| 기존 데이터와 신규 크롤링 결과가 중복됨 | 기존 CSV와 비교해 중복 제거 기준 적용 |
| 질문 검색 범위가 넓어 관련 공지를 찾기 어려움 | 카테고리 점수화로 후보 공지 축소 |
| 팀 프로젝트 구조가 여러 레포로 분리됨 | 시스템 구조 문서와 SVG 도표로 연결 흐름 정리 |

## 7. 회고

크롤링 결과는 챗봇 검색과 필터링에 활용할 수 있도록 구조화되어야 합니다. 본문, 이미지, 링크, 날짜 정보를 하나의 파이프라인에서 정리하면 검색 데이터 품질을 안정적으로 관리할 수 있습니다.
