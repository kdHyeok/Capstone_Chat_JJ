# Chat JJ

전주대학교 공지사항과 학사 정보를 더 쉽게 찾을 수 있도록 만든 스마트 캠퍼스 안내 챗봇 프로젝트입니다.

이 레포는 팀 프로젝트 전체 중에서도 제가 맡았던 공지사항 크롤링, 데이터 정제, 카테고리 분류, 공지 데이터 파이프라인 구축 과정을 정리한 포트폴리오용 저장소입니다.

## 프로젝트 개요

- 기간: 2024.03 ~ 2024.06
- 형태: 전주대학교 캡스톤디자인 팀 프로젝트
- 목표: 흩어져 있는 교내 공지사항과 학사 정보를 수집·정리해, 사용자가 자연어 질문으로 필요한 정보를 더 빠르게 찾을 수 있는 챗봇 서비스 구현

기존 전주대 챗봇은 질문 유형이 제한적이고, 정보 갱신 주기가 불명확하며, 한국어 중심 사용 환경이라는 한계가 있었습니다. 팀은 이런 문제를 개선하기 위해 공지 데이터 자동 수집, 의미 기반 질의응답, 다국어 대응, 사용자 맞춤형 정보 제공 방향으로 Chat JJ를 기획하고 설계했습니다.

## 프로젝트에서 구현한 방향

팀 프로젝트 전체 기준으로는 다음 방향을 목표로 진행했습니다.

- 실시간 공지 크롤링과 데이터 갱신
- 의미 기반 질의응답 구조
- 다국어 입력 및 응답 지원
- 학과·학년·언어 기반 개인화 정보 제공
- 로그인/인증과 서버 연동을 포함한 서비스형 챗봇 구성

주요 기술 요소는 다음과 같습니다.

- RAG 기반 응답 구조
- SBERT 기반 의미 유사도 분석
- LangChain + ChromaDB 활용
- JWT 기반 인증
- OCR 기반 이미지 내 텍스트 추출
- 공지 크롤링 및 마감일 자동 추출

## 내가 맡은 작업

저는 팀에서 크롤링/데이터 수집 파트를 맡아, 챗봇이 참조할 공지 데이터를 모으고 정리하는 기반 작업을 담당했습니다.

주요 기여:

- 전주대학교 공지사항 페이지 크롤링 코드 구현
- 본문, 링크, 이미지 정보 수집 및 정리
- 이미지 기반 공지 내용 OCR 추출 로직 반영
- 공지 데이터 중복 제거 및 정제 파이프라인 구성
- 마감일 자동 추출 로직 정리
- 학사공지/통합공지 분류용 데이터 구조 설계
- 카테고리 분류 기준 정리 및 점수화 로직 제안

단순 수집보다, 챗봇이 실제로 활용할 수 있는 형태로 공지 데이터를 구조화하는 데 집중했습니다.

## 구현 포인트

### 1. 공지사항 수집 자동화

노트북에는 전주대학교 공지 페이지를 순회하면서 공지 목록과 상세 페이지를 가져오는 흐름이 정리되어 있습니다.

- 공지 목록 페이지 순회
- 상세 페이지 본문 수집
- 링크 및 메타데이터 정리
- 업데이트 시 기존 데이터와 비교
- 병렬 처리 적용

### 2. 이미지 기반 정보 보완

공지 내용이 이미지로만 올라오는 경우를 고려해 OCR 흐름도 반영했습니다.

- 공지 본문 내 이미지 링크 수집
- 이미지 텍스트 추출
- 텍스트 기반 후처리
- 본문에 없는 정보 보완

이 작업은 포스터형 공지나 이미지 중심 게시물에서 텍스트 누락을 보완했습니다.

### 3. 마감일 추출과 정제

공지사항에서 중요한 정보는 일정과 마감일인 경우가 많아서, 텍스트에서 날짜 패턴을 찾아 정리하는 로직도 포함했습니다.

- 정규표현식 기반 날짜 후보 추출
- 본문 전처리 후 일정 정보 정리
- 공지별 마감 관련 정보 보강

### 4. 카테고리 분류 기준 설계

질문 응답 품질을 높이려면 수집만으로는 부족하고, 공지의 성격을 구분할 수 있어야 했습니다. 그래서 공지 제목, 본문, 부서 정보를 바탕으로 카테고리 분류 로직을 정리했습니다.

예시 분류 축:

- 수업/강의
- 시험/평가
- 졸업/학위
- 등록/휴학/복학
- 장학/재정
- 행사/일정
- 행정/공지
- 기타

이 단계는 이후 챗봇이 질문 의도와 관련된 공지를 좁혀서 보여주는 데 필요한 전처리 역할을 했습니다.

## 프로젝트 진행 과정에서 확인된 개선 방향

최종 발표 시점에 반영된 개선 방향은 다음과 같습니다.

- 중앙동아리, 학사일정 등 실생활 정보까지 JSON 형태로 관리 범위 확대
- 국제교류원 공지 별도 제공
- 입력 언어 자동 감지와 다국어 응답 구조 보완
- SBERT 기반 유사도 분석과 의미 기반 분류 고도화
- 보안 설정 강화 및 민감 정보 보호 구조 반영

저는 이 중에서도 실제 공지 데이터를 수집하고 정리하는 기반 파이프라인을 맡아, 챗봇이 참고할 원천 데이터를 안정적으로 만드는 쪽에 집중했습니다.

## 내가 이 프로젝트에서 얻은 경험

이 프로젝트를 통해 단순히 데이터를 수집하는 것보다, 서비스가 실제로 사용할 수 있는 형태로 데이터를 구조화하고 유지하는 일이 훨씬 중요하다는 점을 배웠습니다.

특히 다음 경험이 남았습니다.

- 크롤링 결과를 바로 쓰지 않고 정제 가능한 구조로 설계한 경험
- 이미지·본문·링크처럼 형식이 다른 공지 데이터를 한 흐름으로 다룬 경험
- 분류 기준을 직접 정리하면서 데이터 품질과 검색 품질의 연결을 체감한 경험
- 팀 서비스에서 데이터 파이프라인이 AI 응답 품질의 출발점이라는 점을 확인한 경험
