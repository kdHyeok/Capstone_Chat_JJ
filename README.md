# Chat JJ

![Chat JJ 캡스톤 소개 이미지](docs/assets/page_1.png)

"전주대학교 공지사항 안내 챗봇" 팀 프로젝트에서 담당한 공지 데이터 수집·정제 파이프라인을 정리한 저장소입니다.

공지 데이터를 수집·정제하고, 검색에 활용할 수 있는 CSV 형태로 정리했습니다.

## 1. 소개

이 저장소에서 직접 다루는 범위는 공지 목록 수집, 상세 본문 보강, 이미지 OCR, 마감일 추출, 카테고리 점수화, 결과 CSV 병합입니다. 팀 전체 구조는 참고 범위로만 다루고, 이 문서에서는 공지 데이터와 결과 파일 중심으로 정리했습니다.

| 항목 | 내용 |

| 결과 파일 | 통합공지 944건(일반공지 498건, 장학공지 446건), 학사공지 482건 |

## 3. 데이터 파이프라인 요약

![Chat JJ 공지 데이터 파이프라인](docs/assets/cj-data-pipeline.svg)

메인 흐름은 `01_공지_통합_크롤링_파이프라인.ipynb`에서 확인할 수 있습니다. 본문/OCR/마감일 추출과 카테고리 점수화 기준 확인용 노트북은 `notebooks/experiments/` 아래에 분리했습니다.

### 실행 흐름

1. 통합공지·학사공지 목록에서 제목, 부서, 등록일, 상세 링크를 수집합니다.
2. 상세 페이지를 다시 열어 본문과 메타데이터를 보강합니다.
3. 본문 안 이미지 링크를 추출하고 EasyOCR로 이미지 텍스트를 보강합니다.
4. 본문과 이미지 텍스트를 기준으로 마감일 후보와 모집 상태를 정리합니다.
5. 제목, 본문, 이미지 텍스트의 키워드 매칭 결과로 카테고리 점수를 계산합니다.
6. 결과를 CSV로 정리하고 기존 파일과 병합합니다.

### 중복 제거와 병합 기준

- 목록 수집 단계에서는 `공지 제목 + 링크`를 기준으로 1차 중복을 제거했습니다.
- 기존 CSV와 병합할 때는 부서, 제목, 등록일을 조합한 `기본 제목`을 기준으로 다시 정리했습니다.
- `기본 제목`은 같은 제목의 공지가 다른 부서나 날짜로 올라온 경우를 구분하기 위한 병합용 식별 값입니다.

### 카테고리 점수화 기준

- 카테고리 점수는 제목, 본문, 이미지 텍스트의 키워드 매칭 결과를 기준으로 계산했습니다.
- 점수화 비율은 `제목:본문:이미지 텍스트 = 3:2:2`입니다.
- 이 점수는 검색 후보 공지를 먼저 좁히기 위한 전처리 기준으로 사용했습니다.

### 결과 CSV

- `04_통합공지_카테고리분류_결과.csv`: 통합공지 944건(일반공지 498건, 장학공지 446건)
- `05_학사공지_카테고리분류_결과.csv`: 학사공지 482건
- 행 수는 헤더를 제외한 기준입니다.

## 6. 구현

### 공지 목록과 상세 본문 수집

통합공지와 학사공지 게시판을 순회하며 제목, 부서, 등록일, 상세 링크를 수집했습니다. 목록 수집 뒤에는 상세 URL을 다시 열어 본문과 메타데이터를 붙이는 2단계 흐름으로 정리했습니다.

### 이미지 OCR과 마감일 보강

이미지형 공지는 본문 안 이미지 링크를 따로 모은 뒤 EasyOCR로 텍스트를 추출해 `이미지 텍스트` 열에 보강했습니다. 본문과 이미지 텍스트를 함께 읽어 날짜 후보를 찾고, 마감일과 모집 상태를 구조화 열로 분리했습니다.

### 카테고리 점수화

제목, 본문, 이미지 텍스트에서 카테고리별 키워드를 탐지해 점수를 계산했습니다. 점수화 비율은 `제목:본문:이미지 텍스트 = 3:2:2`로 두었고, 이 점수를 검색 후보 공지를 먼저 좁히기 위한 전처리 기준으로 사용했습니다.

### 결과 CSV 병합

신규 수집분과 기존 CSV를 병합한 뒤 `기본 제목` 기준으로 중복을 다시 정리했습니다. 같은 공지가 반복 실행 때 계속 누적되지 않도록 병합 단계에서 등록일 기준 재정렬도 함께 적용했습니다.

## 7. 트러블슈팅

### 1) 이미지형 공지와 비정형 일정 표현 정리

일부 공지는 본문 내용이 이미지에 포함되어 있어 텍스트 수집만으로는 내용이 누락됐습니다. 이 경우 이미지 링크를 따로 수집하고 EasyOCR 결과를 `이미지 텍스트` 열로 보강했습니다.

마감일은 공지마다 표현 방식이 달라 정규표현식으로 후보 날짜를 추출했습니다. `까지`, `마감`, `신청 기간` 같은 표현을 우선적으로 확인하고, 본문과 이미지 텍스트를 함께 사용해 누락 가능성을 줄였습니다.

목록 수집 단계에서는 `공지 제목 + 링크`, 병합 단계에서는 `기본 제목` 기준으로 중복을 정리해 반복 실행 시 결과 CSV 형태가 흔들리지 않게 맞췄습니다.

### 2) 검색 후보 범위 축소를 위한 전처리 기준 분리

공지 수가 늘어나면 질문과 직접 관련 없는 공지까지 한 번에 비교하게 됩니다. 이 저장소에서는 제목, 본문, 이미지 텍스트를 기준으로 카테고리 점수를 계산해 관련 후보를 먼저 좁히는 전처리 단계를 따로 두었습니다.

질문과 가까운 공지를 앞단에서 정리한 뒤 후속 검색 단계가 그 결과를 활용할 수 있도록 역할을 나눴습니다. 이 저장소의 직접 구현 범위는 모델 응답 자체보다 공지 데이터를 같은 형식으로 정리하고 후보 범위를 줄이는 쪽에 가깝습니다.

## 8. 한계 및 개선

- 학교 사이트 HTML 구조가 바뀌면 수집 셀렉터와 본문 추출 로직을 다시 맞춰야 합니다.
- 날짜 표현이 매우 다양한 공지는 정규표현식 패턴을 추가로 보완해야 합니다.
- 카테고리 점수화는 키워드 사전 기반이어서 새 공지 유형이 늘어나면 기준어를 수동으로 보강해야 합니다.
