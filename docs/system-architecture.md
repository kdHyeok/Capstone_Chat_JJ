# Chat JJ 팀 전체 구조 참고

이 문서는 Chat JJ 팀 프로젝트의 전체 연결 구조를 참고용으로 정리한 문서입니다. 이 저장소에서 직접 다루는 범위는 공지 데이터 수집·정제 파이프라인과 결과 CSV입니다.

## 1. 문서 범위

- 직접 구현·정리 범위: 공지 목록 수집, 상세 본문 보강, 이미지 OCR, 마감일 추출, 카테고리 점수화, CSV 생성·병합
- 참고 범위: 앱, 백엔드, AI 서버, 배포 환경
- 도표 구분
  - `assets/cj-data-pipeline.svg`: 이 저장소의 직접 구현 흐름
  - `assets/cj-system-overview.svg`: 팀 전체 구성 참고
  - `assets/cj-runtime-sequence.svg`: 질문 처리 흐름 참고

## 2. 팀 전체 구성 참고

![Chat JJ 전체 시스템 구조](assets/cj-system-overview.svg)

팀 프로젝트는 프론트엔드, 백엔드, AI 서버, 데이터 파이프라인, 배포 자료가 분리된 구조였습니다. 이 문서에서는 전체 맥락을 짧게 남기고, 현재 저장소와 직접 연결되는 지점만 구분해 적었습니다.

| 레포 | 담당 영역 | 역할 |
|---|---|---|
| `CJ_Front` | Flutter 앱 | 화면, 로그인, UI |
| `CJ_Back` | 백엔드 API | 인증, 채팅 API, 데이터 저장 |
| `CJ_AI` | AI 서버 | 검색 데이터 활용, 응답 생성 |
| `CJ_Scraping` | 데이터 수집 파이프라인 | 공지 크롤링, 본문/OCR/마감일 추출, 카테고리 점수화 |
| `CJ_Server` | 서버/배포 자료 | 배포와 운영 자료 |

## 3. 이 저장소의 데이터 파이프라인

![Chat JJ 공지 데이터 파이프라인](assets/cj-data-pipeline.svg)

이 저장소의 중심은 공지 데이터를 검색에 활용할 수 있는 구조화 데이터로 만드는 과정입니다. 메인 흐름은 `../01_공지_통합_크롤링_파이프라인.ipynb`에서 확인할 수 있고, 본문/OCR/마감일 추출과 카테고리 점수화 기준 확인용 노트북은 `../notebooks/experiments/` 아래에 정리했습니다.

### 메인 노트북과 보조 노트북 역할

- `../01_공지_통합_크롤링_파이프라인.ipynb`: 공지 수집부터 CSV 병합까지 한 흐름으로 정리한 메인 노트북
- `../notebooks/experiments/02_공지_본문_OCR_마감일_추출.ipynb`: 상세 본문 수집, 이미지 OCR, 마감일 추출 로직을 단계별로 확인한 보조 노트북
- `../notebooks/experiments/03_공지_카테고리_분류_점수화.ipynb`: 카테고리 키워드 기준과 점수화 비율을 정리한 보조 노트북

### 실행 흐름

| 단계 | 처리 내용 |
|---|---|
| 공지 목록 수집 | 통합공지·학사공지 목록에서 제목, 부서, 등록일, 상세 링크 수집 |
| 상세 본문 보강 | 상세 페이지 본문과 메타데이터 보강 |
| 이미지/OCR 보강 | 이미지 중심 공지에서 이미지 링크를 추출하고 EasyOCR 텍스트 보강 |
| 일정·마감일 추출 | 정규표현식 기반 날짜 후보 추출, 모집 상태 정리 |
| 카테고리 점수화 | 제목, 본문, 이미지 텍스트 기준으로 분류 점수 계산 |
| 결과 병합 | `공지 제목 + 링크` 기준 1차 중복 제거 후 `기본 제목` 기준 병합 |

### 중복 제거와 기본 제목

- 목록 수집 단계에서는 `공지 제목 + 링크`를 기준으로 1차 중복을 제거했습니다.
- 병합 단계에서는 부서, 제목, 등록일을 조합한 `기본 제목`을 기준으로 다시 정리했습니다.
- `기본 제목`은 같은 제목의 공지가 다른 부서나 날짜로 올라온 경우를 구분하기 위한 병합용 식별 값입니다.

### 카테고리 점수화 기준

카테고리 점수는 제목, 본문, 이미지 OCR 텍스트의 키워드 매칭 결과를 기준으로 계산했습니다. 점수화 비율은 `제목:본문:이미지 OCR 텍스트 = 3:2:2`로 두었고, 이 점수를 검색 후보 공지를 먼저 좁히는 전처리 기준으로 사용했습니다.

### 결과 파일

| 파일 | 설명 |
|---|---|
| `04_통합공지_카테고리분류_결과.csv` | 통합공지 944건(일반공지 498건, 장학공지 446건) 분류 결과 CSV |
| `05_학사공지_카테고리분류_결과.csv` | 학사공지 482건 분류 결과 CSV |

행 수는 CSV 헤더를 제외한 기준입니다.

## 4. 질문 처리와 데이터 연결 참고

![Chat JJ 질문 처리 시퀀스](assets/cj-runtime-sequence.svg)

위 도표는 팀 전체 서비스의 질문 처리 흐름을 참고용으로 정리한 자료입니다. 현재 저장소와 직접 연결되는 부분은 아래 두 단계입니다.

1. 공지 데이터를 수집·정제해 검색 가능한 CSV로 만듭니다.
2. 이렇게 만든 CSV와 분류 정보가 후속 검색 단계에서 후보 공지를 좁히는 입력으로 사용됩니다.

런타임 API 경로, 포트, 모델 설정 같은 운영 세부값은 이 저장소의 직접 구현 범위가 아니므로 여기서는 고정 사실처럼 단정하지 않았습니다.

## 5. 직접 확인할 수 있는 구현 포인트

- `BeautifulSoup` 기반 공지 목록·상세 페이지 수집
- `ThreadPoolExecutor` 기반 병렬 수집 구조
- 이미지 링크 추출과 EasyOCR 텍스트 보강
- 정규표현식 기반 마감일 추출
- 제목·본문·이미지 텍스트 기준 카테고리 점수화
- 목록 단계의 `공지 제목 + 링크` 중복 제거와 병합 단계의 `기본 제목` 기준 증분 병합
